# 交付物：干净文书 + 溯源/缺口报告

## 交付两件，不多不少

`references/00-workflow.md` 阶段⑤的 lint 通过之后，本 skill 交付两份产物：

1. **干净文书**——把填充计划渲染进模板得到的成品文档。
2. **溯源/缺口报告**——一份独立的 Markdown，逐项说明每处取值的来源与可信度，并汇总缺口与
   待起草清单。

两者缺一不可：只给文书不给报告，复核人无法判断哪些值是原文摘录、哪些是推算、哪些还没着落；只给
报告不出文书，达不到"填一份模板"的任务目的。

## 干净文书的出法

```bash
python scripts/fill_docx.py <模板> <plan.json> <输出.docx>
```

- **docx 优先**：模板是 `.docx` 且环境装有 `python-docx` 时，脚本就地替换模板段落里的
  `{{slot_id}}` 占位符，产出真实 `.docx`。
- **降级**：缺 `python-docx`，或模板不是 `.docx`（如 `.md`/`.txt` 或其他格式），脚本自动降级为
  markdown 填好稿，返回 `degraded=True`。**必须把这次降级如实告知用户**，说明成品是 markdown 而
  非目标格式的原稿，不得默默交付降级产物而不提示。
- 渲染时，非 `extracted`/`inferred`/`user_confirmed` 的项按脚本内置规则显式打标，不会被悄悄空
  着或填成空字符串：`gap` → `【缺口：<slot_label>】`；`pending_drafting` → `【待起草：<slot_label>】`；
  `ambiguous` → `【存疑·并列待裁：候选1 / 候选2 / …】`。这是脚本自身的行为，agent 不需要也不应该
  在渲染前手工替换这些占位，交给 `fill_docx.py` 统一处理即可保证成文与填充计划一致。

## 溯源/缺口报告格式

报告是一份独立 Markdown，结构如下：

```markdown
# <文书名> 填充溯源报告

本次取证依赖：AnyDocsMarked 知识库 / 普通案卷文件夹（降级，见下方提示）

## 逐项溯源

- **原告姓名**（extracted）：张三
  来源：`_md/民事判决书.md`，locator `p1¶2`，原文："原告张三，男，1980年生"

- **诉请金额**（inferred）：110000
  口径：本金100000 + 利息10000
  依据：`_md/借款合同.md#p2`、`_md/银行流水.md#p5`

- **签约日期**（user_confirmed）：2023年3月1日
  确认：2026-08-17T10:00:00，用户口头确认，卷内无书面

- **违约日期**（ambiguous，未裁定）：候选 2023年6月（催款函）/ 2023年7月（被告答辩）——需人工裁决

- **担保人**（gap）：本案材料中未找到，需人工补充

## 缺口清单
- 担保人：本案材料中未找到

## 待起草清单
- 事实与理由（argument）：留待起草/论证环节生成，未由本 skill 填充

## 覆盖率账本（引用 fill_lint 输出）
extracted: 1  inferred: 1  user_confirmed: 1  ambiguous: 1  gap: 1  pending_drafting: 1
```

- 逐项条目按「`slot_label`（`status`）：值 → 来源信息」的顺序写：`extracted` 附 `source_span`
  三要素；`inferred` 附 `formula` 与 `inferred_from`；`user_confirmed` 附 `confirmed_at` 与
  `confirmation_note`；`ambiguous` 列出全部 `candidates` 及其来源，注明"未裁定"；`gap` 注明
  "本案材料中未找到"。
- 末尾固定三块：**缺口清单**（汇总所有 `gap` 项）、**待起草清单**（汇总所有 `pending_drafting`
  项）、**覆盖率账本**（直接引用 `scripts/fill_lint.py` 打印的各状态计数，不要自己重新数一遍
  产生和脚本不一致的数字）。

## P4 不伪造：成文与报告都要有可见标记

- `gap`、`pending_drafting`、`ambiguous` 三类未定值，在**成文**（干净文书）里必须是可见标记（见
  上文 `fill_docx.py` 的内置渲染规则），不得为了让文书看起来"完整"而私自编一个值填进去，也不得
  留白后不加任何说明。
- 在**报告**里同样要显性列出，不得因为已经在成文里标了就在报告里省略——两处都要能让复核人一眼
  看到哪些还没定。
- 宁可交付一份带缺口标记的文书，也不交付一份看似完整但内容有编造的文书。这是本 skill 的底线，
  优先级高于"客户想要一份看起来完整的文书"这类交付压力。

## 正式交付附免责声明

正式向用户交付文书与报告时，在报告末尾（或文书封面/落款附近，视用户使用场景而定）附一句免责
声明，类似：

> 本文书由 AI 按本案材料自动填充生成，属初步分析结果，不构成最终法律意见，交付前须经执业律师
> 复核（尤其是标记为 `ambiguous`/`gap`/`pending_drafting` 的各项）。

不因文书"看起来已经填满"就省略这句声明；只要是本 skill 产出的成文，就必须带。
