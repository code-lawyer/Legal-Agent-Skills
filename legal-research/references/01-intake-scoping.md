# 建档：法律问题界定 / 事实模式提取

本文件是所有分析模式（研究/检索/复合）的**第一步**，在模式路由结论确定后立即执行。
目的是：在进入检索层（02）之前，把用户的原始输入转化为结构化的检索锚点与分析范围，
明确后续分析的边界和方向。

---

## 一、材料读取纪律（所有模式通用）

### 1.1 全量读取原则

- **读全部上传材料**。用户提交的每一份文件（判决书、合同、委托书、聊天记录截图等）
  都必须纳入建档，不遗漏、不跳过。
- **读取失败必须明说，不静默跳过。**
  若某份材料无法读取（文件损坏、格式不支持、OCR 失败、内容不可提取），
  必须在建档阶段向用户明确报告："《XX文件》读取失败，原因：[具体原因]。
  以下建档基于其余材料，该文件内容不在分析范围内。"
  不得以"已参考全部材料"带过，不得凭推断补填未读内容。

### 1.2 长材料处理纪律

材料较长时（如百页以上判决书、多页合同、大量聊天记录），不要假装读完：

- **先读关键部分**：
  - 判决书：诉讼请求、事实认定、争议焦点、裁判理由、主文。
  - 合同/协议：主要义务、核心条款、争议解决。
  - 其他材料：标题、摘要、签署页、关键事项段落。
- **在建档阶段如实披露阅读范围**：
  > "已读：诉讼请求部分、事实认定节（第3–12页）、裁判理由节（第23–38页）、主文。
  >  暂未详读：质证记录（第13–22页）。如需基于质证细节分析，请提示。"
- 超大材料（如扫描全卷）明说"建议分批提供核心材料，或使用文档转换工具提取关键段落"，
  不强行出结论。

## 二、研究模式建档（法律问题界定）

> 触发：模式路由结论为**研究模式**或**复合模式**。

### 2.1 把诉求转化为疑问句式争议点

用户往往以"我想告XX""我要主张XX""这个条款有没有用"等表达提出需求。
建档时将其转化为法律疑问句式的争议点，便于后续检索与论证：

| 用户原始输入 | 转化后争议点（示例）|
|---|---|
| "这个竞业限制条款能告他吗" | 涉案竞业限制条款是否具有法律约束力？违反后赔偿责任如何认定？|
| "股权转让协议没过工商，合同有效吗" | 股权转让合同未完成工商变更登记，是否影响合同效力？|
| "对方不给付款我能否解除合同" | 付款方逾期未付款是否构成根本违约，守约方是否享有法定解除权？|

- 多个争议点拆开逐个列出，不揉成一锅。
- 争议点的表述精确到"法律关系 + 具体问题"，避免宽泛如"这份合同有没有问题"。

### 2.2 确认最少必要事项

在建档阶段，**仅问信息缺口处真正影响分析方向的事项**，信息够了就不问、不表单化。

以下是研究模式的三项核心确认事项，按需问，而非逐一列出让用户填写：

1. **法律关系**：当事人之间是什么法律关系（劳动、买卖、租赁、股权、侵权等）？
   若上传材料已清楚，无需重复问。
2. **我方诉求/立场**：我方目标是主张权利（起诉/仲裁）、还是防御（被诉/对抗）？
   主张内容是什么（赔偿/解除/确认/执行/撤销）？
3. **关注的争议点**：是否有特别关注的争议点或法律问题？
   有无时效约束（诉讼时效是否届满、法规是否有新修订）？

> 判断原则：若读完材料后上述信息已明确，直接建档，不问；
> 若有关键缺口影响分析走向，只问那一项，一次问清，不分多轮。

### 2.3 研究模式建档产出

建档完成后输出以下结构（向用户披露，确认无误再进入 02）：

```
【研究模式建档】
争议点：
  1. [疑问句式争议点]
  2. [如有多个，分列]
法律关系：[当事人角色 + 关系类型]
我方立场：[主张/防御 + 具体诉求]
分析范围：
  - 材料：[已读文件清单及读取范围；如有读取失败，列出]
  - 法域：中国法（如有其他法域涉及，注明）
  - 时间基准：[如"以现行有效法律为准"，如有时效约束则注明截止点]
下一步：检索核验层（02）
```

## 三、检索模式建档（事实模式提取）

> 触发：模式路由结论为**检索模式**。

### 3.1 事实模式锚点抽取

检索模式的建档核心是从用户提供的事实中抽取类案检索锚点，
确保后续检索式有足够精度，又不过于狭窄而漏检。

逐一抽取以下四个维度的锚点：

| 维度 | 说明 | 示例 |
|---|---|---|
| **案由** | 纠纷类型，尽量精确到具体案由（参照民事案由规定） | 劳动合同纠纷 > 竞业限制纠纷 |
| **关键事实要素** | 决定裁判结果的核心事实（不是所有事实，而是影响法律定性的那些） | 竞业限制协议已签、离职后入职同业竞争者、补偿金已支付 |
| **争议焦点** | 案件最可能发生分歧的核心问题（对应法律要件的争议处） | 竞业限制范围是否过宽导致协议无效；补偿标准是否符合法定最低标准 |
| **当事人类型** | 主体类型与地位（自然人/法企、规模、地域、特殊身份） | 用人单位（互联网公司）+ 普通员工（非高管）|

- 优先用上传材料中已有的信息，不猜测、不脑补缺失字段。
- 若某维度材料中无对应信息（如用户只描述情形未提供具体文件），在锚点中标注"待补充"，
  而非捏造。

### 3.2 补充确认（仅在材料不足时）

检索模式通常无需多问，但以下情形需确认：

- **案由不明**：输入含义模糊（如"这类情况能赢吗"），无法确定案由分类 →
  一句话确认："您指的是[案由A]还是[案由B]？"
- **时间范围**：用户关注裁判倾向时，是否需要限定年份（如近五年）？
- **地域范围**：是否需限定特定法院/省份？全国范围还是特定地区？

> 同研究模式：够用就不问，一次问清，不多轮追问。

### 3.3 检索模式建档产出

```
【检索模式建档】
事实模式锚点：
  - 案由：[精确案由 / 案由分类]
  - 关键事实要素：[逐条列，影响裁判定性的核心事实]
  - 争议焦点：[可能的核心争点]
  - 当事人类型：[主体类型 + 特征]
检索范围：
  - 时间范围：[如"2020年至今"或"近五年"]
  - 地域范围：[全国 / 特定省市 / 最高院]
  - 材料：[已读文件清单及读取范围；如有读取失败，列出]
下一步：检索核验层（02），三轮检索式构造
```

## 四、复合模式建档

> 触发：模式路由结论为**复合模式**（研究问题需类案支撑，或用户要"研究 + 附类案"）。

复合模式同时执行研究模式建档（§2）与检索模式建档（§3），二者合并为一份输出：

```
【复合模式建档】
争议点：[疑问句式，分列]
法律关系与立场：[同研究模式建档]
事实模式锚点：[同检索模式建档]
材料读取：[清单及范围，失败项明说]
下一步：检索核验层（02）→ 研究论证骨架（03）主线，"司法实践"节内嵌检索子流程（04）
```

---

## 五、建档通用安全线

- **不静默补全**：材料中没有的信息，不用推断填充，在建档产出中标"待补充"或直接问。
- **不静默跳过失败**：任何读取失败、解析失败，必须在建档产出中明说，不在后续分析中
  引用未读内容。
- **不预判结论**：建档阶段只做界定和锚点抽取，不输出法律意见，避免建档影响检索偏向。
- **披露范围即承诺范围**：建档产出中列的"分析范围"即后续分析的边界；若后续发现材料
  超出或不足，必须重新披露，不静默扩大或缩小范围。
