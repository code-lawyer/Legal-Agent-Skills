# 检索/归纳骨架

本文件定义**检索模式**（及复合模式内嵌子流程）的七步执行骨架：从事实模式提取到裁判倾向统计、
个案启示，再移交终检门。检索与核验的具体动作（两级级联、三轮留痕、查全/查准 KPI）统一由
`10-retrieval-core.md` 提供，本文件只排步骤顺序与产出结构，不重复定义检索机制本身。

执行本骨架前，建档阶段已产出事实模式锚点（案由、关键事实要素、争议焦点、当事人类型）；
当前法域已确定（默认：中国法）。

**复合模式**：本骨架作为子流程内嵌于研究骨架的司法实践步骤，结果就地呈现在承载步骤中，
不另出独立检索报告；末步移交终检门时，无需为复合模式重复走一遍独立终检，产出随主线一并接受终检。

---

## 步骤一：事实模式提取

**目的**：把建档锚点精炼为可直接驱动检索的结构化输入，同时识别最影响类案相似度判断的
关键事实要素。

**操作**：

1. 取出建档产出的四维锚点（案由、关键事实要素、争议焦点、当事人类型）；若有缺口，此处
   再次确认，仍缺则标"待补充"，不捏造。
2. 对关键事实要素做**权重排序**：
   - 高权重：决定裁判定性的核心事实（如"是否签竞业协议""补偿金是否支付"）——将成为
     步骤三类案相似度判断的主要标准；
   - 低权重：不影响裁判结果的周边事实（合同签订地、具体金额数字等）——不驱动检索式。
3. 明确类案检索的预设范围（时间、地域、审级）。

**输出格式**：

```
【事实模式提取】
案由：[精确案由]
高权重核心事实：[逐条，≤5条]
低权重周边事实：[简列，不驱动检索]
争议焦点：[核心争点]
当事人类型：[主体特征]
检索预设范围：时间 [X年至今] · 地域 [全国/省市] · 审级 [全部/指定]
```

## 步骤二：三轮检索式

**目的**：依托 `10-retrieval-core.md` 的检索核验动作，对候选类案执行三轮检索，每轮留痕，
供报告"检索概述"节原样回显（保证可复现）。

**执行规则**：

- 案例检索走 `10-retrieval-core.md` 的两级级联：MCP 探测 → 命中标 `[MCP核验:源名/案号/裁判
  日期]`；未接或查空 → 回退模型知识，标 `[模型知识-未验证]`。没有其他级次。
- 三轮节奏遵循 `10-retrieval-core.md` § 三轮检索：轮1精确锚点（案由 + 高权重核心事实）→
  轮2近义/别名/上下位扩展 → 轮3去噪/歧义消解（加限定词或裁判日期区间）。
- 每轮结束按 `10-retrieval-core.md` § 检索质量 KPI 做查全率/查准率自评，查全不足则扩大
  检索词、查准不足则加限定词收窄、双不足则重构检索式；决策矩阵与自评过程一并留痕。
- 检索为空时：明确披露"MCP 与模型知识均未检索到"，不编造案号；在步骤六给条件式结论。

**留痕格式（三轮逐一记录，含 KPI 自评）**：

```
轮1检索式：[案由关键词 + 高权重核心事实]
  → 命中：N 件（MCP核验 X / 模型知识 Y）
  → KPI：查全 [达标/不足] · 查准 [达标/不足] → 动作：[扩大/收窄/重构/进入下轮]

轮2检索式：[近义/别名/上下位扩展，或放宽条件]
  → 命中：N 件（在轮1基础上新增 M 件）
  → KPI：……

轮3检索式：[去噪/歧义消解，加限定词或裁判日期区间]
  → 命中：N 件（最终有效候选池）
  → KPI：……
```

三轮汇总后形成**候选案例池**，进入步骤三筛选。

---

## 步骤三：类案筛选

**目的**：对候选案例池做系统性筛选，按相似度加权分层，记录每案纳入或排除的理由，确保
筛选结论可复现（他人按同一标准可得相同结果）。

**相似度分层标准**：

| 层级 | 判定标准 | 报告处理 |
|------|----------|----------|
| **高度类似** | 高权重核心事实全部吻合（≥80%），案由与争议焦点一致 | 全量纳入裁判规则归纳与倾向统计 |
| **部分类似** | 高权重核心事实部分吻合（50%–80%），或案由一致但争议焦点有差异 | 纳入但在报告中注明差异点 |
| **参考** | 仅法律关系或案由相关，核心事实差异显著 | 单独列出，标注差异，不计入倾向统计 |

**评估类案与本案相似度时**，触发 `30-analysis-guardrails.md` 的三层相似度检查：表面相似
（事实要素）→ 结构相似（法律关系构造）→ 目的相似（规范意旨一致，决定性层）；三层缺一层
即不构成"高度类似"，须相应降级。

**筛选操作**：

1. 逐案对照高权重核心事实与三层相似度，逐维度勾选吻合/不吻合，得出层级结论。
2. **记录排除理由**：被排除案例（核心事实完全不符、案号疑似错误、目的层不符）须写排除
   原因，不可静默丢弃。
3. 若候选案例池为空或高度类似案例为零，明确披露，进入步骤五、六时给条件式结论，不强行
   出统计数字。

**输出格式**：

```
高度类似（N件）：[案号列表 + 相似事实摘要 + 三层相似度结论]
部分类似（N件）：[案号列表 + 差异点注明]
参考（N件）：[案号列表 + 差异说明]
排除（N件）：[排除理由简述]
```

## 步骤四：裁判规则归纳

**目的**：跨案提炼裁判规则——不是逐案复述，而是从"高度类似 + 部分类似"案例中归纳法官
说理的**共识规则**与**分歧点**，形成可引用的裁判规则命题。

**归纳操作**：

1. **说理共识**：≥2 件案例共同采纳的裁判逻辑，提炼为规则命题，标支撑案例数与最高效力
   位阶（指导性案例 > 公报案例 > 最高院其他案例 > 高院案例 > 中基层案例）。

   ```
   规则A：[命题表述]——支撑案例：N件（案号1、案号2……）[来源标签]
   最高效力位阶：[指导性案例/公报案例/最高院其他/高院/中基层]
   ```

2. **说理分歧**：不同法院（或同院不同时期）对同一法律要件采用不同认定标准时，并列呈现
   两种说理路径及各自代表案例、支撑数量，不强行统一为一种结论。

   ```
   分歧点X：[争议表述]
     路径甲：[理由] ——代表案例：N件（案号）[来源标签]
     路径乙：[理由] ——代表案例：N件（案号）[来源标签]
   ```

3. 每案引证四字段齐全（案号 / 法院 / 审级 / 裁判日期），来源标签与效力位阶取词与
   `10-retrieval-core.md` 一致。

---

## 步骤五：裁判倾向统计

**目的**：在步骤三纳入的高度类似样本基础上，统计支持/不支持（或其他裁判走向）的比例，
识别影响走向的关键变量。**以诚信披露为前提——样本不足时不强行出比例。**

**统计操作**：

1. **基础统计**：仅对"高度类似"样本做倾向统计（部分类似仅可附注参考，不计入分母）：
   - 支持主张：N 件
   - 不支持主张：N 件
   - 部分支持 / 条件成立：N 件
   - 总样本 N

2. **关键变量分析**（N 足够时展开）：

   | 变量维度 | 分析思路 |
   |----------|----------|
   | **法院层级** | 最高院 / 高院 / 中院 / 基层院的支持率是否有系统差异 |
   | **地域** | 不同省市（经济发达地区 vs 其他）裁判倾向是否存在分化 |
   | **时间趋势** | 近三/五年裁判走向是否有系统性转变（如立法修订后） |

3. **样本不足披露（强制）**：

   - 高度类似样本 N ≤ 5：**必须**在统计段首写明：

     ```
     ⚠️ 样本警示：高度类似案例仅 N 件（N 偏小），以下比例仅供参考，不代表裁判规律，
     请主办律师结合实际情况判断。
     ```

   - 样本为 0 或极少（仅参考层级案例）：跳过比例统计，不强行出数字，改为条件式结论
     （"若事实特征X成立，则倾向Y"），并在步骤六注明"现有样本量不支持倾向性统计结论"。

4. 不以百分比替代实质分析；有条件式结论优于虚假的"50%/50%"。

---

## 步骤六：个案启示

**目的**：将步骤四的裁判规则和步骤五的裁判倾向，具体落到用户事实，给出可操作的预判与
行动建议（**执业级，不学生化占位**）。

**启示层次**：

1. **裁判走向预判**：对照用户事实的高权重核心事实，与"高度类似"样本的胜诉/败诉关键
   事实比较，给出预判（可能性：高/中/低）及核心理由（1–3条）。信息不足时给条件式预判，
   不拒绝下结论。

2. **关键变量对照**：用户事实所属法院层级、地域是否落在步骤五统计中的有利区间？存在
   地域/层级不利因素时，明确提示。

3. **可操作建议**（结合步骤四规则归纳得出）：
   - 补强证据方向：哪些要件事实是胜诉关键，用户目前是否有对应证据。
   - 论点优化：若存在步骤四说理分歧，优先援引效力位阶更高的路径。
   - 时效与时机：是否有近期修法或新发指导性案例改变裁判走向，触发 `10-retrieval-core.md`
     的强制复核触发条件时须建议主办律师强制核验。

4. **局限性说明**：若步骤五已披露样本不足，此处再次注明"建议补充检索后复核启示"；若
   大量来源为 `[模型知识-未验证]`，明确提示"来源核验不足，启示仅供初步参考"。

---

## 步骤七：输出移交与终检

**目的**：将前六步产出装订为可交付的检索报告，过终检门后放行。

- 类案检索报告按 `41-output-case.md` 的六节结构成稿：检索概述（检索式回显 + KPI，对应
  步骤二）/ 类案清单（分层 + 排除理由，对应步骤三）/ 裁判规则归纳（对应步骤四）/ 裁判倾向
  统计（对应步骤五）/ 个案启示（对应步骤六）/ 来源与核验。
- 引证格式、来源标签、免责声明统一走共享引证规范层，不在本骨架重复定义。
- 成稿后移交 `48-qc-gate.md` 逐项终检：来源标签完整性、效力核验、无编造、护栏触发核对、
  置信度门禁、强制核验披露、免责声明七项。终检未通过的项，按其精确回退目标退回对应
  步骤补正（如来源标签缺失回退步骤二/四，样本披露缺失回退步骤五），不静默带过、不跳关
  放行。

> 复合模式下，本骨架产出随承载它的主线步骤一并接受终检，不另出独立检索报告、不重复走
> 一遍独立终检。
