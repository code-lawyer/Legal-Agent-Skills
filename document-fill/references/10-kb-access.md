# 本案知识库探测与接入

## 先说明：软依赖，不 import

本 skill **不 import、不引用 AnyDocsMarked 的任何文件路径**，只在运行时按下述约定去"消费"它的
产物（若存在）。这是 E1 自包含原则的直接体现：把本 skill 单独复制出去，没有 AnyDocsMarked 也能跑
（走降级路径），不会因为缺一个外部项目而报错或失效。

## 第一步：真实探测，不只看配置

拿到案件目录后，**必须实际检查目录结构本身**来判定知识库形态，不能仅凭用户口头说"这是
AnyDocsMarked 案卷"就假定可用；也不能仅凭配置项/环境变量存在就认定可用——配置存在不等于产物
存在。判定标准：

- 案件目录下同时存在 `wiki/` 与 `_md/` 两个子目录，且 `_md/` 下确有可读的 markdown 文件。
- 若有 `rag-retriever`（或同类检索工具）可调用，进一步确认其能对该目录返回检索结果（而非报错
  "索引不存在"）。

两条都满足 → 判定为 **AnyDocsMarked 知识库**，走"有"分支。任一条不满足 → 判定为**普通案卷文件夹**，
走"降级"分支。探测结论要在心里/工作记录里明确一句话："本案知识库探测结果：AnyDocsMarked / 普通
文件夹"，后续阶段按这个结论选取证方式，不得中途混用而不说明。

## 分支 A：AnyDocsMarked 可用

- 取证优先用其**逐字锚点 + 混合检索**能力：按待填项的语义去检索 `_md/` 语料，取回的候选片段本身
  带有可定位的原文出处。
- 每条取到的值，来源信息要落成 `source_span` 三元组：

  ```json
  {"source_id": "_md/借款合同.md", "quote": "本金人民币壹拾万元整", "locator": "p2¶3"}
  ```

  `quote` 必须是能在该来源文件中逐字命中的原文片段（不是转述、不是摘要），供后续
  `fill_lint.py` 的 Mode-2 机检核对。
- 如果 AnyDocsMarked 自带 lint/校验工具，取证完成后可以另外调用它做**二次校验**（例如核对
  `locator` 是否仍指向该版本文档的正确位置）；这是加分项，不是本 skill 的必须步骤——本 skill 自身
  的确定性闸门是 `scripts/fill_lint.py`，二者不互相替代。

## 分支 B：降级——普通案卷文件夹

- 没有 wiki/_md 结构、没有混合检索能力时，改为**人工读取**普通案卷文件夹里的文件（PDF/Word/图片
  OCR 文本等），逐份通读并自行粗检定位待填项所需的信息。
- **必须显性告知用户**降级发生了，措辞类似："本案材料未接入 AnyDocsMarked 知识库结构，本次取证
  为通读案卷文件夹的粗检结果，溯源强度低于逐字锚点检索，且未经确定性 lint 的二次机检覆盖——
  建议人工复核关键数额与日期类待填项。"不得静默降级、假装和分支 A 同等可靠。
- 降级分支下依然要为每条 `extracted` 值填出 `source_span`（`source_id` 用文件名/页码顶替，`quote`
  仍须是原文逐字片段），`fill_lint.py` 的机检规则对两条分支一视同仁，不因降级而放宽。

## 闭世界铁律（两条分支共同遵守）

- **答前必检索**：不得先凭印象/模型记忆写出一个"看起来合理"的值再回头找依据；顺序必须是先在本案
  材料里找到依据，再落值。
- **只用本案材料**：本案材料之外的任何来源（模型训练知识、网络检索、其他案件的经验值）一律不得
  作为填入值的依据，哪怕结果凑巧正确。
- **查不到即 `gap`**：穷尽当前可用的检索/通读手段仍找不到，就是 `status: gap`，`value` 为 `null`，
  不得用推测值、行业惯例值或"通常应该是"这类猜测去填。

## 探测结果影响下游

- 探测结论（AnyDocsMarked / 降级）要带入 `references/20-slot-and-fill.md` 的取证环节，决定每条
  `source_span` 的构造方式；也要带入 `references/30-output-and-report.md` 的报告，在报告开头注明
  本次取证依赖的知识库形态，便于复核人判断可信度。
