# 研究/论证骨架

本文件定义**研究模式**（及复合模式主线）的论证流程：八个分析步骤 + 移交终检门。执行前建档已完成，争议点已转化为疑问句式、逐条列出；检索核验层（`10-retrieval-core.md`）随时可调用。

法域中立：默认中国法，骨架本身不写死任何具体法条；所有检索均经 `10-retrieval-core.md` 的「检索核验(命题, 法域)」动作执行。

**多争议点处置**：逐条独立走完全部步骤，不揉成一锅；一条走完八步再接下一条。步骤间存在依赖时（如争议点B的成立以争议点A为前提），注明依赖关系并按逻辑先后排序。

---

## 步骤一：问题界定

**目的**：把建档产出的争议点转化为本骨架的操作输入。

- 逐条确认争议点已为疑问句式、彼此独立，不把多个争议点揉在一条论证里。
- 对每条争议点标注所属法律部门（合同 / 侵权 / 劳动 / 知产……），锁定本次论证的法律关系。
- 若建档阶段已披露信息缺口且尚未补齐，进入条件式论证，并在步骤八注明所依赖的前提条件。

→ 对应报告「问题与范围」节。

---

## 步骤二：请求权 / 抗辩基础定位

**目的**：在检索之前先定位本争议点的法律结构，避免检索无的放矢。

- **主张方**：识别请求权基础（给付请求权 / 确认请求权 / 形成请求权）。
- **防御方**：识别抗辩路径——实体抗辩（要件不符 / 违法 / 正当理由）与程序抗辩（管辖 / 诉讼时效 / 仲裁前置）。
- 若存在多条并行请求权路径，逐条列出；后续步骤对每条路径分别展开，或汇总论证并注明哪些步骤共用、哪些分叉。
- 本步骤不依赖检索，仅基于建档事实做法律关系定性；定性存疑时明说，不静默绑定单一路径。

---

## 步骤三：法律框架

**目的**：取现行有效法条与司法解释，构建本争议点的规范基础。

- 调用 `10-retrieval-core.md` 的「检索核验(命题, 法域)」，三轮检索覆盖：核心法条（精确条号+款/项）、相关司法解释（正文+施行日期）、最高院《理解与适用》或批复（如有）。
- 每条法条引证须含四字段（法名 / 条号 / 施行日期 / 效力状态）+ 来源标签，并过 `10-retrieval-core.md` 的规范效力检查（七级状态判定）。
- 精确条号、具体数字阈值、近期修订法律等命中 `10-retrieval-core.md` 强制复核触发条件时，不得以模型知识单独支撑。
- 已废止法条仅可作历史沿革引用，不得作为现行依据。

→ 对应报告「法律框架」节。

---

## 步骤四：解释与学说

**目的**：在法条含义存在合理争议处展开解释，为步骤五涵摄提供依据。

- **仅当**法条文义存在合理争议（宽解 / 严解分歧、构成要件认定标准不一）时，触发 `30-analysis-guardrails.md` 的目的解释与体系解释项，呈现主流说与少数说及各自核心理由。
- 学说引用须标注来源层级，不得作为结论的唯一支撑，服务于步骤五的解释框架。
- 若法条含义清晰、学理无实质分歧，本步骤一句话通过（"法条含义明确，无须展开学说争论"），不为凑步骤强行制造争议。

→ 对应报告「解释与学说」节。

---

## 步骤五：涵摄

**目的**：将步骤三/四确定的规范要件适用于本案事实，形成初步法律效果判断。

- 进入涵摄环节时，触发 `30-analysis-guardrails.md` 的涵摄四段模板（大前提 / 小前提 / 涵摄 / 结论），逐段落地，不跳步。
- 同步应用木桶置信度规则：整体置信度取最弱节点，不得对各要素置信度加权平均掩盖。

本步骤产出供步骤七要件分析与步骤八结论与建议调用，不单独对应独立报告节。

---

## 步骤六：司法实践 / 类案

**目的**：以类案检验步骤三/五确定的规范适用在司法实践中的实际走向。

- 调用 `10-retrieval-core.md` 的案例级联检索，按争议点构造检索式；每案引证须含四字段（案号 / 法院 / 审级 / 裁判日期）+ 来源标签 + 权威位阶（指导性案例 > 公报案例 > 最高院其他 > 高院 > 中基层）。
- 类案与本案事实的相似度评估，触发 `30-analysis-guardrails.md` 的三层相似度检查（表面相似 → 结构相似 → 目的相似）。
- **复合模式**：在本步骤内嵌 `21-case-skeleton.md` 子流程（事实模式提取 → 三轮检索式 → 类案筛选 → 裁判规则归纳 → 裁判倾向统计 → 个案启示），结果就地呈现在本步骤中，不另出独立检索报告。
- 类案检索为空时，明确披露"未检索到类案"，不编造案号；在步骤八结论中注明"缺乏类案佐证，结论可靠性受限"。

→ 对应报告「司法实践」节。

---

## 步骤七：要件 · 举证 · 证据

**目的**：将步骤二的请求权路径落实为可操作的举证与证据分析。

- 逐条列出本请求权的构成要件，对照已有事实材料标注"已有证明 / 缺口 / 待补充"；此处触发 `30-analysis-guardrails.md` 的证据-要件挂钩矩阵（★直接 / ○间接）。
- 明确举证责任分配：主张方举证、抗辩方反驳举证、适用举证责任倒置的情形（如特定类型纠纷中一方的书面证据义务）分别列出。
- **因果关系要件涉争时**，触发 `30-analysis-guardrails.md` 的 NESS 切换规则（过度决定 / 双重因果 / 累积因果场景下 But-for 失灵，改用 NESS），并核查最小偏离与 5 类偏差陷阱。
- 结合步骤六类案中对方的抗辩情形，列出对方可能提出的反驳点，供步骤八风险评估使用。

→ 对应报告「要件·举证·证据」节。

---

## 步骤八：结论与建议

**本步骤遵循执业级写作姿态：给实际结论，不采用"只给线索不下结论"的学生化姿态。**

- **实际结论**：直接就本争议点给出结论——主张成立可能性（高 / 中 / 低）+ 核心理由（一至三条）。信息不足时给条件式结论（"若前提A成立则结论为X，若前提B则为Y"），不以不确定为借口拒绝下结论；不得以"建议咨询律师"替代分析。
- 形成结论、给主张成立可能性定级时，触发 `30-analysis-guardrails.md` 的论证强度六维评分（法律依据充分性 / 事实基础扎实度 / 逻辑链完整性 / 反驳意见考量 / 权威支撑位阶 / 结论确定性）与致命缺陷否决规则：法律依据或事实基础任一触底，整体强度直接降级，不得被其余高分加权平均掩盖。
- **裁判风险**：列出 1–3 项主要裁判不利风险（等级 + 理由），来源于步骤六类案的对方胜诉情形、步骤七的证据缺口、步骤四少数说被采纳的可能性。
- **可替代请求**：主请求有被驳回风险时，提出备位 / 替代请求方案及其法律基础与胜诉可能性评估。
- **下一步行动建议**：给出可操作建议（补充哪类证据、核实哪条法条现行状态、协商策略优先级），附时效提示（诉讼时效剩余期间、近期法律修订生效日期）。

→ 对应报告「结论与建议」节。

---

## 步骤九：移交终检门

八步完成后，本次争议点的论证骨架构建完毕：

1. 先按 `40-output-research.md` 的报告结构把论证装订成稿（研究报告）。
2. 再移交 `48-qc-gate.md` 对**成稿报告**逐项终检（七项）；未通过的项按其精确回退目标退回对应步骤补正，不静默带过、不跳关放行。
3. 终检全部通过后方可交付。

> 复合模式下，`21-case-skeleton.md` 子流程已在步骤六内嵌完成，无需为终检重复走一遍独立的检索骨架终检；子流程产出随本骨架一并接受终检。
