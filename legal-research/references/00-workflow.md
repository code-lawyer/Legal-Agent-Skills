# 主流程 + 模式路由 + 数据流骨架

本文件是所有任务的第一步。读完后根据路由结论选择性加载后续分支，不要一次读全。

---

## 一、四模式路由级联

进入后先做模式判定，向用户显示"模式路由结论"后再继续。

| 模式 | 触发特征 | 主线 |
|---|---|---|
| **研究模式** | 输入是一个法律问题或争议点（"……能否""……是否有效""如何认定""论证……"） | 读 `03-research-mode.md`，以论证骨架为主线，案例作论据，产出 `05` 格式报告 |
| **检索模式** | 输入是一组事实/案件类型（"帮我查……类案""这种情形法院怎么判""裁判倾向"） | 读 `04-case-mode.md`，以检索归纳为主线，产出 `06` 格式报告 |
| **复合模式** | 研究问题显含需类案支撑，或用户要"研究 + 附类案" | 以 `03` 为主线，在"司法实践"节内嵌 `04` 子流程；报告走 `05` 并附类案清单 |
| **库维护模式** | 用户要把文档录入法条库/案例库（"录入案例""把这份判决转入库""更新法规"） | 直接走 `08-library-maintenance.md`，独立写入路径，不经研究/检索分析链 |

### 边界模糊时不硬猜

如输入既可能是"论证一个法律问题"也可能是"检索一类案例"，先停下来一句话确认：

> "您的需求是**论证某个具体法律问题**（出研究报告），还是**检索同类案例归纳裁判规则**（出检索报告）？或者两者都需要？"

确认后再路由，不要静默选择。

### 模式路由结论格式

```
模式路由结论：[研究模式 / 检索模式 / 复合模式 / 库维护模式]
问题/任务：<一句话概括>
下一步：读取 <对应文件>
```

将此结论显示给用户，然后继续。

## 二、数据流骨架（三分析模式共用主干）

```
建档/界定(01) → 检索+核验(02，可多轮) → 模式分析(03/04) → 报告产出(05/06) → 时效与引证终检(07)
```

- **01** (`01-intake-scoping.md`)：法律问题界定或事实模式提取，明确检索锚点与范围边界。
- **02** (`02-retrieval.md`)：公共检索核验层，本地库优先 → MCP → 回退模型知识，三轮检索，每轮记录检索式。**所有模式均复用此层**。
- **03/04**：模式分支——研究论证骨架（03）或类案检索归纳（04），由路由结论决定。
- **05/06**：报告产出格式——研究报告（05）或案例检索报告（06），与 03/04 对应。
- **07** (`07-citation-currency.md`)：时效强制核验 + 引证规范 + 来源标签终检，**所有报告产出前必经此步**。

**库维护模式独立路径**：

```
接收文档 → makeitdown 转换 → 法律结构化 → 提案审核 → 写入 corpus + 更新 _index.md (08)
```

库维护的产出（corpus）是 02 中"本地库优先"那一级的源——写入闭环在此形成。

## 三、简单问答捷径

若任务是**小问题**（"某法律条文第几条说什么""某术语定义"），可在骨架内直接作答，无需加载全部分支：

1. 用 02 核验层查一次（本地库 → MCP → 回退）。
2. 挂来源标签，直接回答。
3. 若涉时效敏感点（法条修订、司法解释更新），按 07 强制核验触发规则处理。

不因是"小问题"而跳过来源标签和核验状态。
