# 库维护模式：录入流水线

本文件定义**库维护模式**（触发词：将文档录入法条库/案例库、把判决书/Word 转入库等）的完整执行规程。分工原则：**makeitdown 管"清洗成 md"，本 skill 管"法律结构化 + 入库索引"**，职责不重叠。

---

## 一、库结构双视图

```
corpus/
├── statutes/
│   ├── _index.md          ← agent 检索入口：按字段筛，不必读全部正文
│   ├── 民法典/合同编-租赁合同.md
│   └── 劳动法/劳动合同法.md
└── cases/
    ├── _index.md          ← agent 检索入口：案号/法院/审级/案由/裁判日期/要旨摘要 → 路径
    ├── 劳动争议/(2023)京01民终12345号.md
    └── 房屋租赁/…
```

- **目录层**：按法律部门（法条）/ 案由（案例）分，人类可直接翻阅。
- **`_index.md` 层**：agent 检索真相源，扫该文件即可按字段筛选，命中后再读正文路径。
- **录入必须同时更新两者**：落文件 + 追加索引行，并立即跑一致性检查。

## 二、frontmatter 字段规范

每条 md 正文顶部须含 YAML frontmatter，字段如下（与 `corpus_index.py` 的 `REQUIRED_FIELDS` 一致）：

**法条（7 项必填）：**

```yaml
---
法名: 中华人民共和国劳动合同法
发文机关: 全国人民代表大会常务委员会
条号范围: 第1条—第98条
公布日期: 2007-06-29
施行日期: 2008-01-01
效力状态: 现行有效
来源: 全国人大官网/北大法宝
---
```

**案例（8 项必填 + 1 项可选）：**

```yaml
---
案号: (2023)京01民终12345号
法院: 北京市第一中级人民法院
审级: 二审
案由: 劳动争议
裁判日期: 2023-09-15
裁判要旨: 用人单位未在竞业限制期内支付经济补偿满三个月，劳动者可请求解除竞业限制约定。
关键词: 竞业限制 经济补偿 解除
来源: 中国裁判文书网
当事人: 张某诉XX科技有限公司   # 可选，可脱敏
---
```

## 三、录入流水线（六步，先提案再写入）

### 第一步：转换（调用 makeitdown）

调用 `makeitdown` 将用户提供的 Word / PDF / 扫描件批量转换为高保真 md。

**调用前检查是否已安装：**

```bash
makeitdown --help
```

- 命令存在 → 直接进入第二步。
- 命令不存在 → 按 makeitdown 的 `skill/makeitdown/SKILL.md` 引导安装（提供本地版与云端版两种选择，由用户决定；大陆环境使用 Gitee 镜像与清华 PyPI 源）。**本 skill 不重造转换逻辑。**

**执行转换：**

```bash
makeitdown <原始文档目录> -o <输出目录>
```

法条与案例均走同一转换引擎，输出目录结构与原目录镜像，并生成 `report.json`。

---

### 第二步：质量门（不带病入库）

转换完成后，**优先处理质量问题，再进行法律结构化**：

1. 读取 `<输出目录>/report.json`，提取 `warned` 与 `failed` 列表。
2. 扫描输出 md 的 frontmatter，找到含 `quality: suspect` 的文件。
3. **对以上全部文件**，将可疑段落连同**金额、日期、案号**单独列出，展示给用户核对。
4. 用户确认无误或提供修正后，方可进入下一步；仍存疑的文件暂停入库（见第六步）。

```
⚠️ 质量门报告：
- warned: 2 个文件（report.json）
- failed: 1 个文件（见 report.json failures）
- 以下字段请用户对照原件核对：
  文件 A.md：金额「120,000」（第3页）、日期「2024-03-31」（第7页）
  文件 B.md：案号「(2023)沪01民终????号」识别不全
```

---

### 第三步：法律结构化（抽字段，写 frontmatter）

从通过质量门的干净 md 中抽取法律元数据，写成本库 frontmatter（二、中定义的字段集）：

- **案例**：从裁判文书中抽取案号、法院、审级、案由、裁判日期、裁判要旨、关键词、来源；当事人可抽取后脱敏。
- **法条**：从法规正文中抽取法名、发文机关、条号范围（如收录全文则写全部条文范围）、公布日期、施行日期、效力状态、来源。

字段抽不准时不静默填充，走第六步存疑处理。

---

### 第四步：提案（等待确认，不落文件）

将以下内容完整展示给用户确认，**此步骤不写入任何文件**：

```
=== 录入提案 ===
文件名：(2023)京01民终12345号.md
拟放目录：corpus/cases/劳动争议/
frontmatter（抽取元数据）：
  案号: (2023)京01民终12345号
  法院: 北京市第一中级人民法院
  审级: 二审
  ...（完整字段）
拟写索引行（将追加到 corpus/cases/_index.md）：
  | (2023)京01民终12345号 | 北京市第一中级人民法院 | 二审 | 劳动争议 | 2023-09-15 | 用人单位未在竞业... | 劳动争议/(2023)京01民终12345号.md |

请确认（回复"确认"写入，或指出需修改的字段）：
```

---

### 第五步：写入（确认后执行）

用户回复"确认"（或修改后确认）后，依次执行：

1. **落文件**：将规范化 md 写入拟定目录路径。若目标路径已存在文件，须显式询问"覆盖 vs 取消"，不自动覆盖。
2. **追加索引行**：在对应 `_index.md` 末尾追加 `index_row(...)` 生成的行。
3. **跑一致性检查**，确认无孤儿文件、无悬空索引、无案号重复：

   ```bash
   # 案例库一致性检查
   python -c "
   import sys; sys.path.insert(0, '.')
   from corpus_index import check_consistency
   r = check_consistency('corpus/cases', 'cases', 'corpus/cases/_index.md')
   print(r)
   "
   ```

   ```bash
   # 法条库一致性检查
   python -c "
   import sys; sys.path.insert(0, '.')
   from corpus_index import check_consistency
   r = check_consistency('corpus/statutes', 'statutes', 'corpus/statutes/_index.md')
   print(r)
   "
   ```

4. 若 `check_consistency` 返回非空 `duplicates`（案号重复）：**提示用户判断"新版本 vs 重复录入"**，不自动决定，等待用户指令后再处理重复项。

**字段校验示例**（写入前或出现字段疑问时调用）：

```bash
python -c "
import sys; sys.path.insert(0, '.')
from corpus_index import parse_frontmatter, validate_record
text = open('corpus/cases/劳动争议/(2023)京01民终12345号.md', encoding='utf-8').read()
meta = parse_frontmatter(text)
msgs = validate_record(meta, 'cases')
print(msgs if msgs else '字段校验通过')
"
```

---

### 第六步：存疑处理（标出问用户，不静默入库）

以下情况一律暂停、标注、等待用户决定，**不静默入库以免污染检索库**：

| 情况 | 处理方式 |
|------|----------|
| 字段抽不准（如裁判日期格式混乱、法名截断） | 展示原始文本片段，请用户核实并提供正确值 |
| 案号识别存疑（如仅有非正式摘录，括号/年份缺失） | 标注"案号待核实"，挂起该文件，待用户确认后继续 |
| `quality: suspect` 未经第二步核对 | 不进入结构化，返回第二步 |
| `check_consistency` 检出案号重复 | 明确提示"已存在相同案号，请确认是新版本还是重复录入" |
| 覆盖或删除已有库文件 | 显式确认，说明路径，等待明确指令 |

---

## 四、安全线小结

- **写入前必须展示提案**（propose-then-confirm），用户确认后方可落文件。
- **覆盖/删除需显式确认**，不自动执行。
- **案号重复不自动覆盖**：`check_consistency` 的 `duplicates` 触发提示，由用户判断新版本 vs 重复。
- **质量有疑问的文件不入库**：宁可暂停问用户，也不带病入索引污染检索。
- **案号/条号编造为零容忍**：字段抽取失败时，填"待核实"并报告，不脑补值。
