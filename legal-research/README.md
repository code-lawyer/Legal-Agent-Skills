# 法律研究与案例检索 Skill

面向**文件系统类 AI agent**（能读文件、能遍历目录：Claude Code / Codex / Cursor / Cline / Copilot CLI / Gemini CLI 等）的技能：接收法律问题或一组事实，经公共检索核验层（本地库 → MCP → 回退），产出**执业律师级**研究报告或类案检索报告；并提供一条用户自维护的本地语料库写入路径。

> ⚠️ **交付单元是整个 `legal-research/` 文件夹，不是单个 `SKILL.md`。** SKILL.md 只是入口索引，正文（流程/方法/骨架/报告模板）在 `references/` 里，运行时由 agent 按需读取。只把 SKILL.md 一个文件交出去会导致 agent 读不到这些文件。

---

## 一、用途

本 skill 交付两类报告，并负责维护产出这些报告所依赖的本地语料库：

| 交付物 | 触发场景 |
|---|---|
| **法律研究报告** | 论证某法律问题/争议点（"能否解除""是否有效""如何认定""论证……"） |
| **案例检索报告** | 检索类案/裁判规则（"帮我查这类合同纠纷怎么判""同案同判分析""裁判倾向"） |
| **本地语料库写入** | 把判决书/Word/PDF 转入本地案例库或法条库 |

---

## 二、四模式

### 研究模式
输入是一个法律问题或争议点。走 `01 建档 → 02 检索核验 → 03 论证骨架 → 05 研究报告 → 07 时效引证终检`。产出含八节结构的法律研究报告（执行摘要、问题与范围、法律框架、学说、司法实践、分析/要件/举证/证据、结论与建议、来源与核验）及免责声明。

### 检索模式
输入是一组事实或案件类型。走 `01 → 02（三轮检索式留痕）→ 04 类案归纳 → 06 检索报告 → 07`。产出含检索式回显、类案清单、裁判规则归纳、裁判倾向统计、个案启示、来源与核验六节的类案检索报告及免责声明。

### 复合模式
研究问题显含需类案支撑，或用户要"研究 + 附类案"。以 `03` 为主线，在"司法实践"节内嵌 `04` 类案子流程；报告走 `05` 格式并附类案清单。

### 库维护模式
用户要把文档录入法条库/案例库。直接走 `08 录入流水线`，独立写入路径，不经研究/检索分析链。执行六步：makeitdown 转换 → 质量门 → 法律结构化 → 提案（先展示不写入）→ 确认后写入 + 更新索引 → 一致性检查。

## 三、安装与运行

### Python 工具（corpus 管理）

要求 **Python 3.8+**。核心脚本位于 `legal-research/`：

```bash
# 校验 skill 结构完整性（每次修改 references/ 或 corpus/ 后运行）
cd legal-research
python validate.py

# 运行所有单元测试
python -m pytest tests/ -v
# 预期：11 passed（7 corpus_index + 4 validate）
```

无需安装额外依赖，validate.py 与 corpus_index.py 仅使用 Python 标准库。

### makeitdown（录入模式专用）

录入 Word/PDF/扫描件判决书需要 makeitdown 将原始文档清洗为高保真 md。

检查是否已安装：

```bash
makeitdown --help
```

- **已存在**：直接进行库维护操作。
- **不存在**：按 `skill/makeitdown/SKILL.md` 中的说明安装（提供本地版与云端版；大陆环境可用 Gitee 镜像 + 清华 PyPI 源）。本 skill 不重造转换逻辑，调用 makeitdown 作为外部命令。

## 四、corpus 语料库维护

### 目录结构

```
corpus/
├── statutes/
│   ├── _index.md          ← agent 检索入口（字段化，快速筛选）
│   └── <法律部门>/        ← 人类可翻阅的分类目录
└── cases/
    ├── _index.md          ← agent 检索入口（案号/法院/审级/案由/裁判日期/要旨）
    └── <案由>/            ← 人类可翻阅的分类目录
```

**双视图设计**：目录层供人类浏览，`_index.md` 供 agent 字段检索——录入时必须同时更新两者（落文件 + 追加索引行），之后立即跑 `check_consistency` 确认无孤儿/悬空/重复。

### 录入纪律

- **先提案再写入（propose-then-confirm）**：法律结构化完成后，完整展示文件名、拟放目录、frontmatter 字段、拟写索引行，等待用户确认后才落文件。
- **案号重复不自动覆盖**：`check_consistency` 检出重复时提示用户判断"新版本 vs 重复录入"，不静默决定。
- **质量有疑问的文件不入库**：makeitdown 转换后，先过质量门（`report.json` 的 warned/failed 列表 + `quality: suspect` 标记），人工核对金额、日期、案号无误后方可结构化入库。
- **覆盖已有文件需显式确认**：目标路径已存在时，询问"覆盖 vs 取消"，不自动覆盖。

## 五、MCP（可选）

核验层可插拔：运行时探测当前环境接上的专业法律库 MCP（北大法宝/法信/元典等），接上则实时核验并标 `[MCP核验:源名/案号或条号/日期]`；未接则回退模型知识并标 `[模型知识-未验证]`。不写死任何具体 MCP 名称，以实际探测结果填入。

## 六、免责声明

每份正式交付（含研究报告与检索报告）均附以下免责声明，不得省略：

> **本报告为基于所提供材料、本地法规语料库及公开检索结果的专业分析，不构成最终法律意见，不替代主办律师对具体个案的判断与签字责任。**
>
> 本报告所引法条及司法解释以检索时现行版本为准；凡未经外部源核验的命题均已在报告"来源与核验"节标注，据此行动前请经执业律师复核确认。
>
> 标注 `[模型知识-未验证]` 的命题不得作为诉讼或法律交付物的唯一依据。

## 七、边界（与 contract-review-cn-us 的分工）

| 本 skill（legal-research） | contract-review-cn-us |
|---|---|
| 法律研究报告（论证法律问题） | 合同审查 + 风险清单 |
| 类案检索报告（裁判规则归纳） | 可选 Word 红线稿 |
| 本地语料库维护 | — |

**本 skill 不做**：合同审查（请使用 `contract-review-cn-us`）、合同起草、企业核验、尽调合规、续约提醒、流程图。

## 八、获取

**方式 A（推荐，使用者）—— 从 Releases 下载压缩包**
到本仓库 [Releases](../../releases) 下载 `legal-research-<版本>.zip`，解压得到完整的 `legal-research/` 文件夹。

**方式 B（维护者）—— 克隆源码**
```bash
git clone https://github.com/Tsinglaw/Legal-Agent-Skills.git
```
skill 位于 `legal-research/`。

解压或克隆后，把 `legal-research/` 文件夹交给 agent（放进 skill 目录，或让 agent 读取并遵循 `legal-research/SKILL.md`）。skill 会自定位：所有内部路径相对 `SKILL.md` 所在目录解析，与当前工作目录无关。
